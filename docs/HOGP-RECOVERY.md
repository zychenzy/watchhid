# HOGP recovery and regression checks

## Cause and protection
Foreground-dependent dynamic reads of immutable device/HID metadata returned ATT242 on initialization; BTLEServer timed out and never created its native mouse node. A subscribed Report or a successfully read Map was not sufficient evidence. Normal launch now uses the accepted standard128 recipe with cached read-only Map, HID Information, manufacturer, model and PnP ID. Mouse Report, battery and writable attributes remain dynamic. Diagnostic dynamic variants remain available separately.

Removed speculative missing-Map-read republish and automatic neutral-on-subscription: cached metadata intentionally generates no application read callback, so absence of that callback must not tear down a working mouse. Restored the accepted R1 identity rather than using model bumps as a cache nudge.

The successful experiment changed both static metadata and equivalent full-length advertising UUID representation. Their individual causal contributions have NOT yet been fully isolated. Runtime watchOS peripheral SDK availability limitations and foreground-only input remain; this is not a promise of permanent background operation.

## Safety
Only the known Mac as sole Report subscriber plus active scene enables mouse input. Settings, system text input and preview block touchpad input, release held buttons and discard queued motion. Returning to the panel may auto-arm but requires a fresh gesture. No movement is generated by launch/subscription. English keyboard remains default-off; system text entry only presents captured String for review, never automatically types it into Mac.

## Reversible deployment
Known accepted baseline source6d62b8e and signed rollback archive are preserved locally. Advanced merge3d714db preserves large pad, tap-left, hold-right and bottom system text-entry button. No push, Bluetooth cache reset, unpair, system restart or Mac input helper.

Automated checks: compile Shared mouse/keyboard/metadata/descriptors with scripts/MouseInputStateTests.swift as main.swift; run12 evidence-gate tests in scripts/test_assess_live_read.py. Tests validate both metadata report-map modes, immutable bytes, dynamic-only writable/report attributes, inactive right-button release, no stale gesture replay and subscription-loss disarm. They do not replace actual macOS cursor acceptance.

## Voice primary action
The bottom orange microphone action is explicitly labeled语音听写. It retains the existing public nil-suggestions/plain WatchKit text-input call, accepted by the user after selecting the microphone. The installed SDK exposes no microphone-only/default-method parameter; the language overload supplies suggestions for the current language and explicitly does not go straight to dictation. No private API, system-page auto-click, or input-language/system setting modification. A non-modal help sentence lives in Settings and in the button accessibility hint, not in a repeating alert and not at the expense of touchpad area. Whether this watchOS remembers the last dictation mode remains unverified.

## Remaining initialization failure
After the final wording-only reinstall, native BTLEServer again reported ATT242 and timed out without recreating the mouse. No HID recipe had changed. One unchanged remote restart did not recover it. Static immutable metadata is a useful accepted repair, not a complete solution for every foreground/launch timing. Exact remaining failing dynamic attribute is not isolated. At09:07 HKT Watch and iPhone were unavailable after the user left home, so no further hardware attempts were made. The last installed19e2b13 is installed but needs a fresh manual foreground-open/short-drag acceptance; the packaged successor changes only simulator-only checks and documentation on device.
